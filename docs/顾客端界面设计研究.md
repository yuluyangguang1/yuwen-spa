# 足浴/按摩/SPA 行业顾客端扫码界面设计研究报告

> **项目**：yuwen-spa 顾客端（GuestView）  
> **研究日期**：2026-10-02  
> **研究范围**：行业竞品、移动端 UX 最佳实践、设计趋势、具体设计建议

---

## 一、行业竞品分析

### 1.1 美团/大众点评到店服务界面

**核心设计模式：**
- **门店首页**：头图轮播 + 评分/销量/距离 + 团购套餐列表
- **团购详情**：价格锚点（原价 vs 团购价）+ 销量 + 评价摘要 + 购买按钮
- **核销后**：显示"已核销"状态 + 评价入口 + 再次购买推荐

**可借鉴点：**
- 价格锚点设计（原价划线 + 团购价高亮）
- 销量社会证明（"已售 2000+"）
- 评价摘要前置（显示最新/最有用的评价）
- 核销状态明确（绿色对勾 + "已核销"）

**局限性：**
- 面向"到店前"决策，缺少"到店中"服务过程管理
- 无技师选择、无服务进度、无加钟等场景

### 1.2 抖音团购核销后界面

**核心设计模式：**
- **核销成功页**：大对勾动画 + "核销成功" + 门店信息 + 评价引导
- **评价引导**：五星评分 + 标签选择（"服务好""环境好"）+ 文字评价
- **复购推荐**："猜你喜欢" + 相似团购

**可借鉴点：**
- 核销成功动画（即时正反馈）
- 标签化评价（降低评价门槛）
- 复购推荐（提升客单价）

**局限性：**
- 同样缺少服务过程管理
- 评价流程过于简单，缺少技师维度

### 1.3 足浴/按摩/SPA 行业 SaaS 顾客端

#### 博卡（Boka）
- **技师选择**：列表式，显示技师照片、等级、擅长项目、当前状态（空闲/服务中）
- **服务进度**：时间轴式，显示"已开钟 30 分钟 / 共 60 分钟"
- **加钟**：独立页面，选择加钟项目 + 确认

#### 美业管家
- **技师卡片**：卡片式，显示技师头像、姓名、等级、评分
- **项目选择**：分类列表（足浴/按摩/SPA），显示时长、价格
- **服务进度**：进度条 + 剩余时间 + 技师信息

#### 有赞美业
- **门店首页**：品牌头图 + 门店信息 + 技师列表 + 项目列表
- **技师详情**：照片 + 等级 + 擅长项目 + 评价
- **下单流程**：选技师 → 选项目 → 确认 → 支付

**可借鉴点：**
- 技师状态实时更新（空闲/服务中/休息）
- 服务进度可视化（进度条 + 剩余时间）
- 技师评价展示（评分 + 评价数）
- 加钟流程简化（一键加钟）

**局限性：**
- 多为小程序，依赖微信生态
- 设计较为传统，缺少创新交互
- 未充分利用移动端特性（如手势、动效）

### 1.4 餐饮扫码点单

**核心设计模式：**
- **首页**：门店 Logo + 菜单分类 + 推荐菜品
- **菜单**：分类 Tab + 菜品列表（图片 + 名称 + 价格 + 加购按钮）
- **购物车**：底部悬浮栏 + 已选数量 + 总价 + 去结算
- **下单**：确认订单 + 备注 + 提交

**可借鉴点：**
- 分类 Tab 导航（快速切换）
- 购物车悬浮栏（随时查看已选）
- 加购动画（飞入购物车）
- 备注输入（个性化需求）

**局限性：**
- 面向"点餐"场景，缺少"服务过程"管理
- 无技师概念

## 二、移动端 UX 最佳实践

### 2.1 扫码后的第一印象设计（Landing Page）

**核心原则：**
1. **3 秒原则**：用户扫码后 3 秒内必须理解"这是什么"和"我能做什么"
2. **品牌一致性**：第一印象必须与门店线下品牌一致
3. **状态明确**：立即告知用户当前房间状态（空闲/使用中）

**设计建议：**
- **品牌头图**：门店 Logo + 品牌色 + 欢迎语
- **房间状态卡片**：大字号显示"房间空闲"或"服务中"
- **主操作按钮**：根据状态显示"选择技师"或"查看进度"
- **辅助信息**：门店地址、联系电话、营业时间

**反模式：**
- 直接显示复杂表单（用户还没理解上下文）
- 加载时间过长（超过 2 秒）
- 信息过载（一次性展示太多内容）

### 2.2 信息架构（IA）：顾客最需要看到什么信息

**优先级排序（从高到低）：**

| 优先级 | 信息 | 原因 |
|--------|------|------|
| P0 | 房间状态 | 决定用户下一步操作 |
| P0 | 当前服务进度 | 服务中最关心的信息 |
| P1 | 技师信息 | 建立信任感 |
| P1 | 服务时长/剩余时间 | 管理预期 |
| P2 | 费用明细 | 透明消费 |
| P2 | 加钟/点单入口 | 增值服务 |
| P3 | 评价入口 | 服务后反馈 |
| P3 | 门店信息 | 辅助信息 |

**信息架构建议：**
```
首页（房间状态）
├── 空闲状态
│   ├── 选技师（HoloCard 3D 卡片）
│   │   └── 技师详情（照片/等级/擅长/评价）
│   ├── 选项目（分类列表）
│   └── 确认下单（费用明细 + 过夜选项）
├── 使用中状态
│   ├── 服务进度（进度条 + 剩余时间）
│   ├── 技师信息（头像 + 姓名 + 等级）
│   ├── 加钟（项目列表）
│   └── 点单（食物用品）
└── 服务完成
    └── 评价（评分 + 标签 + 文字）
```

### 2.3 交互模式：卡片式 vs 列表式

**卡片式适用场景：**
- 技师选择（需要展示照片、等级、状态等丰富信息）
- 项目选择（需要展示时长、价格、描述）
- 服务进度（需要展示进度条、时间、技师信息）

**列表式适用场景：**
- 点单菜单（商品数量多，需要快速浏览）
- 评价标签（标签数量多，需要快速选择）
- 历史订单（订单数量多，需要快速查找）

**设计建议：**
- 技师选择：**卡片式**（HoloCard 3D 全息卡片是亮点）
- 项目选择：**卡片式**（每个项目独立卡片，显示时长/价格）
- 服务进度：**卡片式**（大卡片，突出进度条和剩余时间）
- 点单菜单：**列表式**（分类 Tab + 商品列表）
- 评价标签：**标签云**（可多选，快速选择）

### 2.4 手势操作

**适用场景：**
- **下拉刷新**：刷新房间状态、服务进度
- **左滑**：删除/隐藏（如隐藏忙碌技师）
- **长按**：快捷操作（如长按技师卡片查看详情）
- **双击**：点赞/收藏（如收藏技师）

**设计建议：**
- 服务进度页支持下拉刷新（获取最新进度）
- 技师列表支持左滑隐藏（隐藏不感兴趣的技师）
- 项目列表支持左滑加购（快速加入购物车）

### 2.5 暗色模式在移动端的应用

**优势：**
- 节省电量（OLED 屏幕）
- 减少眩光（适合足浴店昏暗环境）
- 突出内容（深色背景 + 高对比度内容）
- 品牌调性（高端、私密、放松）

**设计建议：**
- 背景色：#0a0a09（现有）
- 卡片色：rgba(255,255,255,0.05)（现有 glass-card）
- 主文字：#ffffff
- 次文字：rgba(255,255,255,0.6)
- 强调色：tan（#d4a574 或类似）
- 成功色：moss（绿色）
- 警告色：cinnabar（红色）

**注意事项：**
- 避免纯黑（#000000），使用深灰（#0a0a09）更柔和
- 确保文字对比度 ≥ 4.5:1（WCAG AA 标准）
- 图片/头像需要适配暗色模式（避免过亮）

### 2.6 大字号/大按钮的适老化设计

**足浴店用户特点：**
- 年龄偏大（30-60 岁为主）
- 可能佩戴老花镜
- 手指可能不灵活（按摩后）

**设计建议：**
- 最小字号：14px（正文），16px（按钮）
- 按钮高度：≥ 48px（触控目标）
- 按钮间距：≥ 8px
- 关键信息字号：≥ 18px（如剩余时间、费用）
- 对比度：≥ 4.5:1

**现有系统评估：**
- ✅ 按钮高度合理（py-3 = 48px）
- ✅ 字号合理（text-sm = 14px）
- ⚠️ 部分辅助文字偏小（text-[10px] = 10px）
- ⚠️ 评价标签可能偏小

## 三、设计趋势

### 3.1 2024-2025 移动端 UI 设计趋势

**1. 玻璃拟态（Glassmorphism）**
- 半透明背景 + 模糊效果
- 层次感 + 深度感
- 适合高端品牌（如足浴/SPA）

**2. 新拟态（Neumorphism）**
- 柔和阴影 + 凸起/凹陷效果
- 适合按钮、卡片
- 但可访问性较差，需谨慎使用

**3. 3D 元素**
- 3D 图标、3D 卡片
- 增强视觉冲击力
- 适合技师卡片（如 HoloCard）

**4. 微交互（Micro-interactions）**
- 按钮点击反馈
- 加载动画
- 状态切换动画

**5. 手势驱动导航**
- 滑动切换 Tab
- 下拉刷新
- 左滑操作

**6. 个性化推荐**
- 基于历史行为的推荐
- 基于评分的排序
- 基于偏好的筛选

### 3.2 毛玻璃/全息/3D 效果在移动端的应用

**毛玻璃（Glassmorphism）：**
- 适用场景：卡片、弹窗、导航栏
- 实现：backdrop-filter: blur(20px)
- 注意：性能开销，低端设备可能卡顿

**全息（Holographic）：**
- 适用场景：技师卡片、品牌展示
- 实现：WebGL / CSS 3D 变换
- 注意：需要降级方案（2D 图片）

**3D 效果：**
- 适用场景：技师卡片、项目展示
- 实现：CSS 3D 变换 / WebGL
- 注意：触控交互（拖动旋转）

**现有系统评估：**
- ✅ 已使用 glass-card（毛玻璃卡片）
- ✅ 已使用 HoloCard（WebGL 3D 技师卡片）
- ⚠️ 需要确保低端设备降级方案

### 3.3 微交互和动效设计

**关键微交互：**

| 场景 | 动效 | 目的 |
|------|------|------|
| 下单成功 | 对勾动画 + 颜色变化 | 即时正反馈 |
| 服务进度 | 进度条平滑过渡 | 减少焦虑 |
| 加钟成功 | 卡片飞入动画 | 增强满足感 |
| 评价提交 | 星星点亮动画 | 增强参与感 |
| 技师选择 | 卡片翻转/放大 | 增强选择感 |

**设计建议：**
- 使用 CSS transition（性能优于 JS 动画）
- 动画时长：200-500ms（太快感觉突兀，太慢感觉卡顿）
- 使用 ease-out 缓动曲线（自然减速）
- 提供"减少动画"选项（可访问性）

### 4.3 交互流程优化建议

#### 4.3.1 下单流程优化

**现有流程：**
```
选技师 → 选项目 → 确认下单 → 等待接单
```

**优化建议：**
```
选技师（HoloCard 3D 预览）
    ↓
选项目（分类 Tab + 卡片列表）
    ↓
确认下单（费用明细 + 过夜选项）
    ↓
下单成功（动画 + 等待接单）
    ↓
自动刷新 → 服务进度
```

**优化点：**
1. **技师预览**：点击 HoloCard 显示技师详情（照片/等级/擅长/评价）
2. **项目分类**：按类别 Tab 切换（足底/全身/精油/SPA）
3. **费用透明**：确认页显示费用明细（项目费 + 过夜费）
4. **下单反馈**：下单成功显示动画 + 等待接单状态
5. **自动刷新**：下单后自动刷新，显示服务进度

#### 4.3.2 服务进度优化

**现有流程：**
```
服务进度（进度条 + 剩余时间）
    ↓
加钟（选择项目）
    ↓
点单（食物用品）
```

**优化建议：**
```
服务进度（大卡片 + 进度条 + 剩余时间）
    ├── 技师信息（头像 + 姓名 + 等级 + 评价）
    ├── 加钟（一键加钟 + 项目列表）
    ├── 点单（分类 Tab + 商品列表）
    └── 服务完成 → 评价
```

**优化点：**
1. **进度可视化**：大卡片 + 进度条 + 剩余时间（大字号）
2. **技师信息**：显示技师头像、姓名、等级、评价
3. **加钟简化**：一键加钟（默认 30 分钟）+ 项目列表
4. **点单入口**：全局悬浮按钮 + 服务进度页入口
5. **服务完成**：自动弹出评价引导

#### 4.3.3 评价流程优化

**现有流程：**
```
服务完成 → 评价引导（浮动按钮）→ 评价页面
```

**优化建议：**
```
服务完成 → 评价引导（全屏卡片）→ 评价页面
    ↓
评分（五星）→ 标签（多选）→ 文字（可选）→ 提交
    ↓
评价成功（动画 + 感谢）
```

**优化点：**
1. **评价引导**：服务完成后自动弹出评价引导（全屏卡片）
2. **评分简化**：五星评分 + 标签选择（降低门槛）
3. **标签预设**：预设标签（服务好/技术好/环境好/态度好）
4. **匿名评价**：默认匿名（保护隐私）
5. **评价反馈**：提交成功显示动画 + 感谢语

## 五、局域网部署特殊性考虑

### 5.1 网络环境

**特点：**
- 无外网访问
- 手机扫码连接局域网 Wi-Fi
- 网络可能不稳定（信号弱、干扰）

**设计建议：**
1. **离线支持**：使用 Service Worker 缓存静态资源
2. **重试机制**：API 请求失败自动重试（指数退避）
3. **超时处理**：设置合理的超时时间（如 10 秒）
4. **错误提示**：网络错误显示友好提示（"网络不稳定，请重试"）
5. **本地存储**：使用 localStorage 缓存技师/项目数据

### 5.2 设备兼容性

**特点：**
- 顾客手机型号多样（iOS/Android）
- 屏幕尺寸多样（4.7" - 6.7"）
- 性能差异大（高端旗舰 vs 低端入门）

**设计建议：**
1. **响应式设计**：使用 Tailwind 响应式类（sm/md/lg）
2. **性能优化**：
   - 图片懒加载（loading="lazy"）
   - 虚拟列表（长列表优化）
   - WebGL 降级方案（低端设备使用 2D 图片）
3. **触控优化**：
   - 按钮最小 48px
   - 间距最小 8px
   - 支持手势操作（下拉刷新、左滑）

### 5.3 扫码体验

**特点：**
- 顾客使用微信/支付宝/系统相机扫码
- 扫码后打开浏览器（非 App）
- 可能需要登录/授权

**设计建议：**
1. **免登录**：使用 roomId 作为唯一标识（现有方案）
2. **URL 简洁**：`/guest/room/:roomId`（现有方案）
3. **加载优化**：
   - 首屏加载时间 < 2 秒
   - 使用骨架屏（Skeleton）减少等待焦虑
   - 渐进式加载（先显示房间状态，再加载技师列表）
4. **错误处理**：
   - 无效 roomId 显示友好提示
   - 网络错误显示重试按钮
