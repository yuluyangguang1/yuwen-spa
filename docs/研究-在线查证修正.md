## 一、重大修正：「点钟影响轮转」的结论与子代理报告相反

### 子代理报告的说法（❌ 有误）

`研究-排钟机制.md` 第 126-131 行：

> **推荐做法（主流）**：点钟**不改变**轮转位置。
> **理由**：点钟是顾客主动选择，不是技师"轮到"的机会...

### 在线查证到的行业主流做法（✅ 有据）

来源：**索易软件足道研究院**（21 年行业经验，10000+ 门店）
<https://www.soesoft.net/article/5771647893556522>

> **方式二：点钟优先制**
> **规则**：轮钟照常运转，但顾客点某位技师的时候，这位技师直接被调出队列去上钟，
> **上完钟后排回队尾**。

> **缺点**：点钟多的技师，轮钟机会可能变少（因为经常被点走、每次都从队尾排），
> 可能出现"点钟多反而总收入不高"的情况

**关键差异**：行业主流的「点钟优先制」中，点钟技师**上完钟后要排回队尾**，
而**不是**「不影响轮转位置」。子代理报告把这一点说反了。

### 但「点钟不计入轮钟」确实存在——作为另一种模式

同一来源的「方式四：提成+排钟双轨制」：

> **规则**：轮钟和点钟采用不同的提成比例，比如点钟提成更高；
> 同时在排钟排序上做平衡——点钟多的技师适当补偿轮钟排位，
> **或者点钟不计入轮钟排序但有额外奖金**。

**结论**：「点钟是否计入轮转」**是门店可配置的策略**，两种做法都真实存在：

| 做法 | 出处 | 适用 |
|------|------|------|
| 点钟后**排回队尾** | 索易「点钟优先制」 | 需要平衡技师收入 |
| 点钟**不计入轮钟** | 索易「提成+排钟双轨制」 | 点钟提成已足够激励 |

**对本项目的启示**：这应该是**配置项**，不是硬编码的单一规则。

## 二、行业标准排钟方式（权威分类，可直接落地）

来源同上（索易足道研究院），这是查证到的**完整分类**：

### 2.1 顺序轮排制（最基础）

```
规则：技师按固定排钟号排队，来客派队首，上完钟排到队尾，循环。
优点：规则最简单、绝对公平、前台省事
缺点：无激励性、优秀技师留不住、顾客不能指定
适合：小型门店（5 人以下）、技师水平接近
```

### 2.2 点钟优先制

```
规则：轮钟照常运转，顾客点某技师时该技师被调出队列上钟，上完钟排回队尾。
优点：激励服务质量、顾客体验好、回头客多
缺点：点钟多的技师轮钟机会变少，可能"点钟多反而总收入不高"
适合：中小型门店、技师有水平差距、重视回头率
```

### 2.3 分等级轮排制

```
规则：技师按技术水平/工龄/星级分 A/B/C 组（或金/银/铜牌），
      每级价格不同，顾客选等级，每个等级内部各自轮排。
优点：拉开收入差距、顾客按需选择
缺点：等级评定要公平透明、低等级技师提升慢、管理复杂
适合：中大型门店（15 人以上）、项目分级定价
```

### 2.4 提成+排钟双轨制

```
规则：轮钟和点钟用不同提成比例（点钟更高）；
      排钟排序上做平衡——点钟多的补偿轮钟排位，或点钟不计入轮钟但有额外奖金。
优点：既激励又公平、收入差距可控
缺点：规则复杂、必须系统支撑、设计不好两头不讨好
适合：中大型门店
```

### 2.5 预约优先制

```
规则：预约单优先安排技师档期，散客在预约空档里穿插。
优点：预约客体验好、可提前规划排班
缺点：散客等待久、爽约浪费严重、系统要求高
适合：高端门店、会员制、线上预售
```

### 2.6 横向对比（原文表格）

| 排钟方式 | 公平性 | 激励性 | 顾客体验 | 管理复杂度 | 适用规模 |
|----------|--------|--------|----------|------------|----------|
| 顺序轮排制 | 高 | 低 | 一般 | 极低 | 小店（5 人以下） |
| 点钟优先制 | 中 | 高 | 好 | 低 | 中小型 |
| 分等级轮排制 | 中 | 高 | 好 | 中 | 中大型（15 人+） |
| 提成+排钟双轨制 | 中高 | 高 | 好 | 高 | 中大型 |
| 预约优先制 | 中 | 中 | 预约客好 | 中高 | 高端/会员制 |

**原文重要提醒**：

> 上面说的 5 种都是纯理论模式。实际开店的，很少有用单一方式的，基本都是**混合模式**。
> 比如：轮钟+点钟（最常见）、分等级+点钟优先、预约+散客混合...

> 没有最好的排钟方式，只有最适合的。

## 三、「跳钟」的定义分歧（重要）

### 子代理报告的说法

`研究-排钟机制.md` 第 55-59 行：

> **跳钟（跳过钟）**：轮转到某技师时，该技师正在服务中（或在忙/休息），
> 系统跳过该技师，分配给下一位。

### 在线查到的另一种定义（来源：百度文库《足疗按摩洗浴行业术语大全》）

通过搜索 snippet 获取（原页 403，未能抓全文）：

> **跳钟**：宾客即将接受保健服务时，又另行挑选技师，称为跳钟。**跳钟不算点钟**。
> 被放弃的技师如果不是服务和技术质量问题，此技师**仍排回原位**；
> 否则，取消此钟，并按公司[规定处理]

**这是完全不同的语义**：

| 说法 | 触发者 | 含义 |
|------|--------|------|
| 子代理版 | 系统 | 技师在忙，系统自动跳过 |
| 百度文库版 | 顾客 | 顾客临场改选技师 |

### 我的判断

**两个定义可能都真实存在，但用于不同语境**：

- 「顾客临场改选技师」→ 更接近**顾客行为**，行业里也叫「跳牌」
- 「技师在忙被跳过」→ 更接近**系统行为**，是排钟算法的内部机制

**建议**：本项目采用时，用更明确的命名避免歧义：

```
tech_busy_skip    技师在忙被跳过（系统行为）
customer_switch   顾客临场改选（顾客行为）
```

不要直接沿用「跳钟」这个有歧义的词做字段名。

## 四、查证失败的部分（诚实记录）

以下术语**在公开网络上未找到权威定义**，子代理报告中的说法**无法证实也无法证伪**：

| 术语 | 查证状态 |
|------|----------|
| 挂钟 | ❌ 未找到权威定义。360/百度返回的多是娱乐向内容或"买钟"的混淆 |
| 留钟 | ❌ 未找到权威定义 |
| 落钟 | ❌ 未找到权威定义。搜索无有效结果 |
| 扣钟 | ⚠️ 查到的说法是「扣钟即是加钟」（与子代理报告不同，但来源可信度一般） |

**这个"查不到"本身是重要信息**：

说明这些术语**在行业内并非标准化术语**，更可能是**特定门店/地区/软件厂商的自造词**。
行业公认的核心概念只有：

```
轮钟（顺序轮排）  ← 有权威定义
点钟（指定技师）  ← 有权威定义
加钟（延长服务）  ← 有权威定义
排钟员            ← 确认存在此角色
上钟/下钟         ← 有定义（开始/结束服务）
```

**结论**：不要按"七种钟型"的框架硬做设计。应该按**实际业务需要**建模，
而不是为了凑齐七种术语而引入没有实际用途的字段。

## 五、搜索过程中确认的其他事实

### 5.1 「排钟员」是真实存在的岗位

搜索结果中出现：「足疗店上钟是指技师接到**排钟员**[的安排]...」

说明传统足浴店有专职「排钟员」负责派钟。这**验证了本项目「客服派单台」的定位**——
数字化后，排钟员的职责由客服端承担。

### 5.2 「上钟/下钟」是标准术语

- **上钟**：技师开始为客人服务
- **下钟**：服务结束，技师离开按摩区到排钟员处作记录

本项目的 `started_at` / `completed_at` 字段正对应这两个概念。

### 5.3 提成复杂度是行业公认痛点

来源（知乎专栏 snippet）：

> 足浴店的提成算法天然复杂：**点钟、加钟、推卡、不同项目不同比例**。
> 分开买的系统，每套各自记流水，月底要把三份报表拼起来，再人工核对
> 「这笔钱到底算谁的」。

**验证了本项目已有 `commission_cents` 字段的必要性**，但当前实现较简单
（只按项目比例/固定值），未区分点钟/轮钟的提成差异。

## 六、对本项目设计的具体影响

### 6.1 排钟模式应该是可配置的，不是硬编码

```js
// 建议：门店级配置（存 meta 表或 settings）
{
  rotation_mode: 'round_robin' | 'point_priority' | 'level_grouped',
  point_counts_in_rotation: false,   // 点钟是否计入轮转
  level_grouping_enabled: false,     // 是否分等级轮排
}
```

理由：行业主流是**混合模式**，没有单一正确答案。

### 6.2 本项目最适合的起点

考虑到项目现状：

```
技师数量：示例数据 3 人（实际门店可能 5-20 人）
已有字段：level（初级/中级/高级）、is_star（明星技师）
已有能力：AI 推荐（评分/负载/技能匹配）
缺失：轮转顺序、轮转公平性
```

**建议从「点钟优先制」起步**（行业最常见，索易列为中小型门店首选）：

```
1. 顾客指定技师（点钟）→ 直接派单，上完钟排回队尾
2. 顾客不指定 → 按轮转顺序派下一个空闲技师
3. AI 推荐作为客服的辅助参考（可选，不强制）
```

这比「纯顺序轮排」更符合足浴店实际（有明星技师体系），
也比「分等级轮排」简单（不需要重构定价体系）。

### 6.3 需要澄清的一个矛盾

项目现有 `level` 字段（初级/中级/高级）和 `is_star`（明星技师），
但**不参与定价**（`services.price_cents` 是统一的）。

索易的「分等级轮排制」要求**每个等级价格不同**。
所以本项目当前的数据模型**不支持分等级轮排**——除非改造定价体系。

**这是个需要用户决策的产品问题**，不是技术问题。
