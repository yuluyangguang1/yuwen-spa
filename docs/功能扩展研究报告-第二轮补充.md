## 一、足浴垂直品牌对比（六大品牌）

来源：索易软件选型指南 `soesoft.net/article/5758808887768733`（2026-08-06）

行业主流品牌：**中顶、智络、博卡**（三大）+ 索易、客多多、足浴管家、智铺子。

| 品牌 | 核心优点 | 功能局限 | 适配场景 |
|------|----------|----------|----------|
| **中顶** | 入局早，基础收银成熟稳定，定价亲民，上手简单 | 足浴垂直功能少；**排钟规则样式单一**；**不支持阶梯提成、点钟专项奖励**；无成熟预约小程序；**无法对接抖音/美团团购** | 仅需基础记账的老式小店 |
| **智络** | 会员储值、次卡、套餐管理完善；界面简洁 | **通用美业系统改造**，非足浴专用；钟房管控基础；**换钟/加钟/停钟逻辑不细化**，复杂场景易核对偏差 | 会员储值为主、排钟场景少的小店 |
| **博卡** | 多业态适配，稳定性强，数据安全完善 | 侧重美容美发足浴通用；**纯足浴精细化不足**；**跨房换钟、技师轮排优化、加班专属提成缺失** | 美业综合门店 |
| **索易** | 覆盖点钟/排钟/钟房/自定义提成/会员/预约小程序；**支持离线营业、全域团购自动核销、多模式薪资核算、连锁管控** | 学习周期长；轻量版性价比一般；高级版收费高 | 单店到连锁全类型 |

### 1.1 关键情报：云端 vs 本地部署

这是**对本项目最有参考价值的一段**（本项目是本地部署）：

| 维度 | 本地版 | 云端版 | 索易的混合方案 |
|------|--------|--------|----------------|
| 网络依赖 | 断网可正常营业 | **断网无法开单/收银/排钟** | 离线缓存 + 联网自动同步 |
| 数据安全 | 本地存储，需人工备份，**有丢失风险** | 云端多重自动备份 | 云 7 重加密备份 + 本地双备份 |
| 远程管理 | **不支持远程登录查账** | 支持随时随地远程查看 | 老板移动端后台 |
| 系统迭代 | 更新多为收费，节奏慢 | 免费持续迭代 | 全年免费迭代 |
| 连锁适配 | 多门店数据割裂 | 支持多门店互通 | 总部统一定价，单店可差异化 |

**结论（原文）**：
> 传统本地版系统存在管理功能滞后、远程管控缺失、迭代更新慢的问题，
> 纯云端版系统存在断网停业的营业风险。2026年足浴门店可优先考虑**混合部署模式**。

**对本项目的启示**：
本项目的本地部署路线是**正确且被验证的**——行业公认云端版的最大缺陷正是
"断网无法营业"。但本项目需要补上本地版的三个短板：
1. **备份自动化**（本项目已有 `backup.js`，但需确认是否自动定时）
2. **老板远程查账**（本项目是局域网，外出时看不到——可考虑只读外网通道或定期推送报表）
3. **迭代更新机制**

### 1.2 六大核心功能（行业选型标准）

行业公认足浴收银软件的核心刚需：

```
1. 点钟管理
2. 智能排钟
3. 技师提成核算
4. 钟房管控
5. 会员体系运营
6. 顾客预约小程序
```

索易自称内置 **12 种排钟规则**（轮钟、点钟等全覆盖）。
**对照本项目**：6 项中，钟房管控（房间管理）✅，其余 5 项均为薄弱或缺失。

## 二、商业通用 SaaS 对标（有赞 / 微盟 / 客如云 / 思迅）

### 2.1 微盟

来源：`weimob.com`

有**两个产品线与足浴场景直接对口**：
- **智慧服务-预约锁客**：「聚焦服务类商家**智能预约与次卡锁客**场景，
  将人工操作转为标准化流程，提升效率与服务体验」
- **智慧生活-本地生活**：「适配本地生活**服务+商品模式**，
  打造**预约、锁客、会员运营闭环**」

其他相关产品线：智慧门店（收银+进销存+多渠道销售+店务管理）、
会员（全域会员多渠道统一管理、标签洞察、分层运营）、企微助手（私域）。

**可借鉴**：「预约锁客」+「次卡」的组合思路——对应足浴店的
"预约到店 + 次卡消费"，本项目已有预约和储值，缺次卡。

### 2.2 有赞

来源：`youzan.com`、`youzan.com/solution`

核心能力矩阵：
- **全渠道流量变现**：多渠道线上商城（微信小程序等）+ 营销工具（秒杀、团购、满减）
- **导购/粉丝分销**：分销平台、佣金体系、裂变式/佣金式/代理制
- **精细化会员运营**：全渠道会员管理、会员画像、行为分析、
  **会员体系（等级、积分、储值、特权）**、自动化精准营销（节日促销、生日营销）
- **线上线下一体化**：数字化门店管理、订单同步门店履约、多种支付

**可借鉴**：会员等级 + 积分 + 储值的组合；生日营销（本项目 `customers.birthday` 字段已存在但未使用）。

### 2.3 客如云

来源：`keruyun.com`（餐饮为主，但引流模式值得参考）

- **引流获客**：「打通短视频、外卖、**团购平台**，助营收增长，沉淀会员资产」
- **会员营销**：「丰富营销玩法，科学建立**会员成长体系**，提频复购」
- **智能体**：「让老板省心省力，辅助决策，赋能管理」
- 提到**抖音代运营**、数智供应链

**可借鉴**：把团购平台的客户**沉淀为会员资产**——
这是"团购客人转私域"的思路，正是本项目团购核销功能的延伸价值。

### 2.4 思迅

来源：`siss.com.cn`（石基信息成员企业，股票代码 838758）

产品矩阵庞大（商旗/商云/智选/小象/考拉/烘焙家/天店等），
覆盖零售、餐饮、商超、便利店、生鲜、专卖、烘焙等。

**注意**：思迅的行业方案里**没有足浴/按摩**——进一步印证
足浴是垂直细分市场，通用厂商不覆盖。

## 三、会员储值方案设计（行业实操）

来源：搜狐《2026门店会员储值怎么设计》`sohu.com/a/1082542083_122761128`

这部分**直接可用于本项目的产品设计**。

### 3.1 储值档位：分三档起步

| 档位 | 目的 | 说明 |
|------|------|------|
| **体验档** | 门槛低 | 让头回进店的顾客愿意跨出第一步 |
| **主力档** | 覆盖大多数常客 | **日常营收基本盘** |
| **深度档** | 已认可门店的老客 | 长期消费意愿一次性沉淀 |

**关键提醒**（原文）：
> 档位之间的差额不要拉得太开。相邻两档如果跨度太大，
> 中间那档会直接空掉，客户要么充最低档试试，要么直接冲最高档，
> **主力档反而没人碰**。

### 3.2 赠送设计：不要直接送钱

原文观点：
> 充多少送多少是最省脑子的做法，**也是最容易亏的做法**。
> 送的金额看着热闹，其实直接吃掉毛利，而且顾客记住的是送的那部分。

**更耐用的做法——把赠送拆成两类**：
1. **送权益而不是送钱**：专属折扣、某项目免费体验、生日月额外权益
2. **送次卡而不是送余额**：余额想花就花，次卡定向用在某项目上，
   既能带动体验，也能避免余额被套现

**成本原则**：赠送成本必须算进单店毛利模型，看复购和到店频次能否补回。

### 3.3 储值 + 次卡组合

| 方式 | 好处 | 坏处 |
|------|------|------|
| 纯储值 | 灵活 | **顾客卡里有钱但不来**，钱趴在账上 |
| 纯次卡 | 锁定项目 | **次数用不完容易闹退费** |

**组合做法**（推荐）：
- 充值得到**可消费余额**，任意项目抵扣
- 按档位**赠送若干次指定项目体验次数**，引导尝试平时不会点的服务
- **次卡按次消耗，余额按金额消耗，两本账分开记**，对账清晰

**关键**：组合规则要在充值前讲清楚——余额能否转赠、次卡能否延期、不同项目怎么扣。

### 3.4 有效期设计

**核心矛盾**（原文）：
> 不设有效期，看起来大方，实际上沉淀下来的预收款会变成**长期负债**。
> 有效期设得太短，顾客刚觉得不错就被催着用完，体验直接崩掉。

**中庸做法**：
1. 设合理有效期，覆盖顾客正常复购周期
2. **到期前通过短信或小程序消息提醒一次**，别等过期才说
3. 对确实没用完的顾客，给**一次性延期方案**，而不是直接作废
4. **退费规则在充值协议里写明白**，系统支持手动办理退费
5. **课消明细、余额变动都留痕**，顾客能自查每一笔扣在哪里

### 3.5 对照本项目现状

| 储值能力 | 行业标准 | 本项目 |
|----------|----------|--------|
| 多档位配置 | 三档（体验/主力/深度） | ⚠️ 有 `topup-commission-rules` 档位，但是**提成档位**，非储值赠送档位 |
| 充值赠送 | 送权益/送次卡（非送钱） | ⚠️ 需确认是否支持赠送 |
| 次卡 | 按次消耗，独立记账 | ❌ 缺失（`customers` 有余额但无次卡） |
| 余额+次卡分离 | 两本账分开记 | ❌ 缺失 |
| 有效期管理 | 可配置 + 到期提醒 | ⚠️ 需确认 |
| 余额变动留痕 | 明细可查 | ✅ 有 `wallet_transactions` |
| 退费 | 协议明确 + 系统支持 | ✅ 有 `topup-refund` |

**最重要的缺口是「次卡」**——行业公认储值+次卡组合是标准做法，
而本项目只有储值余额，没有次卡。这也是微盟「预约锁客」产品线的核心。

## 四、补充结论

### 4.1 对本项目路线的验证

1. **本地部署是对的**。行业公认云端版最大缺陷是"断网无法营业"，
   而足浴店网络环境常不稳定。本项目的本地优先路线被市场验证。
2. **但本地版有三个公认短板需要补**：备份自动化、远程查账、迭代机制。
3. **通用 SaaS 不覆盖足浴**。思迅的产品矩阵里没有足浴；
   有赞/微盟虽有"本地生活/智慧服务"产品线，但偏营销侧，缺排钟体系。
4. **垂直品牌也有明显缺口**。中顶不支持团购核销和阶梯提成；
   智络换钟/加钟逻辑不细化；博卡纯足浴功能不足。
   → **本项目的排钟体系做扎实，就能超过多数垂直品牌。**

### 4.2 新增缺口（本轮补充）

| 缺口 | 行业标准 | 优先级 |
|------|----------|--------|
| **次卡** | 储值+次卡组合是标准做法 | P1 |
| **储值赠送档位** | 三档 + 送权益/送次卡 | P1 |
| **会员等级** | 等级+积分+储值+特权 | P2 |
| **生日营销** | 生日月专属权益 | P2（字段已有） |
| **团购客转会员** | 把团购客户沉淀为会员资产 | P2 |
| **远程查账** | 老板外出可看经营数据 | P2 |
| **到期提醒** | 储值/次卡到期前提醒 | P2 |
