# 局域网扫码技术方案研究报告

> **项目背景**：yuwen-spa 是本地部署的足浴店管理系统，单机跑在店里的小主机上，局域网访问，无公网域名，无 HTTPS 证书。技术栈：Node.js + Fastify 5 + React 19 + Vite，前端已构建为 PWA。
>
> **调研目标**：增加「进店大堂码」，顾客在店里扫码进入 H5 选项目下单。本报告聚焦局域网（无公网、无 HTTPS）环境下手机扫码访问 H5 的技术约束与最佳实践。
>
> **诚实声明**：本报告基于公开技术文档和通用知识撰写。由于网络限制，部分浏览器行为未能实时验证，凡不确定处均明确标注「未验证，建议实测」。

---

## 一、二维码 URL 设计

### 1.1 方案对比

| 方案 | 示例 | 优点 | 缺点 | 推荐度 |
|------|------|------|------|--------|
| **局域网 IP** | `http://192.168.1.100:8080/guest/lobby` | 简单直接，无需额外配置 | IP 会变（路由器重启、DHCP 重新分配） | ⭐⭐⭐ |
| **mDNS (.local)** | `http://yuwen.local:8080/guest/lobby` | 域名固定，不依赖 IP | iOS Safari 支持有限，微信内置浏览器可能不支持 | ⭐⭐ |
| **主机名** | `http://yuwen-pc:8080/guest/lobby` | 易记 | 依赖 NetBIOS/mDNS，跨平台兼容性差 | ⭐ |
| **公网域名 + 内网穿透** | `https://yuwen.example.com` | 稳定，支持 HTTPS | 需要公网服务器，违背「本地优先」原则 | ❌ |

### 1.2 推荐方案：局域网 IP + 静态分配

**核心建议**：使用 `http://<局域网IP>:8080/guest/lobby` 作为大堂码 URL，并通过路由器 DHCP 静态分配或主机静态 IP 确保 IP 不变。

**具体操作**：

#### 方案 A：路由器 DHCP 静态分配（推荐）

1. 登录路由器管理界面（通常 `192.168.1.1` 或 `192.168.0.1`）
2. 找到「DHCP 设置」→「静态地址分配」或「地址保留」
3. 将运行 yuwen-spa 的小主机的 MAC 地址与固定 IP 绑定（如 `192.168.1.100`）
4. 重启小主机，确认获取到固定 IP

#### 方案 B：主机静态 IP

在运行 yuwen-spa 的小主机上配置静态 IP：

**Linux（以 systemd-networkd 为例）**：
```ini
# /etc/systemd/network/20-wired.network
[Match]
Name=eth0

[Network]
Address=192.168.1.100/24
Gateway=192.168.1.1
DNS=192.168.1.1
```

**Windows**：
- 设置 → 网络和 Internet → 以太网 → 编辑 IP 设置 → 手动
- IPv4 地址：`192.168.1.100`，子网掩码：`255.255.255.0`，网关：`192.168.1.1`

### 1.3 IP 变化容错设计

即使做了静态分配，仍可能出现 IP 变化（路由器更换、网络重构）。建议：

1. **多 IP 二维码**：在二维码中同时编码多个可能的 IP（如主 IP + 备 IP），前端检测当前哪个可用
2. **动态二维码**：使用电子墨水屏或小型显示屏，定期刷新显示当前 IP 对应的二维码
3. **手输降级**：在二维码旁边标注「如扫码失败，请手动输入 `http://192.168.1.100:8080`」
4. **mDNS 备用**：同时配置 mDNS（如 `yuwen.local`），在支持的环境中使用

### 1.4 mDNS 方案评估

**mDNS（多播 DNS）** 允许通过 `.local` 域名访问局域网设备，无需 DNS 服务器。

**支持情况**：
- **Android Chrome**：支持 mDNS，可以访问 `http://yuwen.local:8080`（Android 12+ 默认开启）
- **iOS Safari**：iOS 14+ 支持 mDNS，但行为不稳定，部分版本可能无法解析（**未验证，建议实测**）
- **微信内置浏览器**：基于 X5 内核（Android）或 WKWebView（iOS），mDNS 支持不确定（**未验证，建议实测**）
- **桌面浏览器**：Chrome、Edge、Firefox 均支持 mDNS

**配置方法**：

在 Linux 小主机上安装并配置 Avahi：
```bash
sudo apt install avahi-daemon
sudo systemctl enable avahi-daemon
sudo systemctl start avahi-daemon
```

确保主机名设置为 `yuwen`（修改 `/etc/hostname`），即可通过 `http://yuwen.local:8080` 访问。

**结论**：mDNS 可作为备用方案，但不应作为唯一方案，因为微信内置浏览器的支持不确定。

## 二、微信扫码限制

### 2.1 微信内置浏览器对 HTTP 局域网地址的支持

**核心结论**：微信内置浏览器（基于 X5 内核或 WKWebView）**可以打开 HTTP 局域网地址**，但存在以下限制：

1. **非 HTTPS 页面中的部分 API 受限**：
   - 微信 JS-SDK 的 `wx.config` 需要 HTTPS 才能使用完整功能
   - 但普通 H5 页面（不调用微信 JS-SDK）可以正常访问 HTTP 局域网地址

2. **微信扫码打开外部链接的行为**：
   - 微信「扫一扫」可以识别二维码并打开链接
   - 对于 HTTP 链接，微信会提示「即将打开外部浏览器」或在内置浏览器中打开（**具体行为未验证，建议实测**）
   - 部分微信版本可能对 HTTP 链接有安全提示

3. **微信支付限制**：
   - 如果需要在 H5 中调用微信支付，**必须使用 HTTPS**
   - HTTP 页面无法调用微信支付（微信 JS-SDK 要求安全上下文）

### 2.2 微信扫码对非标准端口的支持

**结论**：微信扫码**支持非标准端口**（如 `:8080`）。

- 二维码中的 URL 可以包含端口号，如 `http://192.168.1.100:8080/guest/lobby`
- 微信内置浏览器会正确解析并访问该地址
- **未验证，建议实测**：部分旧版本微信可能对非标准端口有兼容性问题

### 2.3 支付宝扫码

支付宝扫码行为与微信类似：
- 可以打开 HTTP 局域网地址
- 支持非标准端口
- 支付宝支付同样需要 HTTPS

### 2.4 系统相机扫码

iOS/Android 系统相机扫码后：
- **iOS**：会在 Safari 中打开链接，支持 HTTP 局域网地址
- **Android**：会在默认浏览器中打开，支持 HTTP 局域网地址

## 三、浏览器安全上下文要求

### 3.1 需要 HTTPS 安全上下文的 Web API

以下 API **仅在安全上下文（HTTPS 或 localhost）中可用**：

| API | 用途 | HTTP 局域网下是否可用 |
|-----|------|----------------------|
| **Service Worker** | PWA 离线缓存 | ❌ 不可用（localhost 除外） |
| **getUserMedia** | 摄像头/麦克风访问 | ❌ 不可用 |
| **Geolocation API** | 地理位置 | ❌ 不可用 |
| **Clipboard API** | 剪贴板读写 | ❌ 不可用（部分浏览器支持） |
| **Web Speech API** | 语音识别/合成 | ⚠️ 部分支持（见下文） |
| **WebRTC** | 实时通信 | ❌ 不可用 |
| **Payment Request API** | 支付 | ❌ 不可用 |
| **WebAuthn** | 生物识别认证 | ❌ 不可用 |

### 3.2 localhost 例外规则

**关键结论**：`localhost` 被视为安全上下文，但**局域网 IP（如 `192.168.1.100`）不被视为 localhost**。

- `http://localhost:8080` → 安全上下文 ✅
- `http://127.0.0.1:8080` → 安全上下文 ✅
- `http://192.168.1.100:8080` → **非安全上下文** ❌
- `http://yuwen.local:8080` → **非安全上下文** ❌

**影响**：在局域网 IP 访问时，Service Worker 无法注册，PWA 离线功能失效。

### 3.3 语音识别（Web Speech API）在 HTTP 局域网下的行为

**项目已有 VoiceInput 组件**，需要特别关注：

- **Chrome/Edge**：Web Speech API（`SpeechRecognition`）在 HTTP 局域网下**可能可用**，但行为不一致（**未验证，建议实测**）
- **Safari**：Safari 的 Web Speech API 支持有限，且要求安全上下文（**未验证，建议实测**）
- **微信内置浏览器**：X5 内核可能不支持 Web Speech API（**未验证，建议实测**）

**建议**：
1. 在 HTTP 局域网环境下测试语音识别功能
2. 如不可用，提供手动输入作为降级方案
3. 考虑使用第三方语音识别服务（需 HTTPS）

### 3.4 无 HTTPS 环境下功能失效清单

| 功能 | 是否失效 | 影响 |
|------|----------|------|
| Service Worker 注册 | ✅ 失效 | PWA 无法离线缓存 |
| 摄像头扫码 | ✅ 失效 | 无法使用摄像头扫码（但顾客是用微信/系统相机扫，不依赖此 API） |
| 麦克风语音输入 | ⚠️ 可能失效 | 语音点单可能不可用 |
| 地理位置 | ✅ 失效 | 无法获取顾客位置（足浴店场景可能不需要） |
| 剪贴板 | ✅ 失效 | 无法复制粘贴（影响较小） |
| 微信支付 | ✅ 失效 | 无法在 H5 中调用微信支付 |
| 普通页面浏览 | ✅ 正常 | 核心功能不受影响 |
| API 请求（fetch） | ✅ 正常 | 与后端通信不受影响 |

## 四、PWA 离线能力

### 4.1 Service Worker 在 HTTP 局域网下的注册

**核心问题**：Service Worker 要求安全上下文，HTTP 局域网 IP 无法注册。

**影响**：
- PWA 无法离线缓存
- 断网时无法显示基础信息
- 无法实现「添加到主屏幕」的 PWA 安装提示（部分浏览器要求 Service Worker）

### 4.2 替代方案

#### 方案 A：使用 Cache API 手动缓存（有限）

虽然 Service Worker 不可用，但可以使用 `Cache API` 配合 `fetch` 事件拦截（需要 Service Worker，所以此方案不可行）。

#### 方案 B：使用 LocalStorage/IndexedDB 缓存数据

```javascript
// 缓存关键数据到 localStorage
localStorage.setItem('shopInfo', JSON.stringify(shopInfo));
localStorage.setItem('menuItems', JSON.stringify(menuItems));
```

**限制**：只能缓存数据，无法缓存 HTML/CSS/JS 文件本身。

#### 方案 C：接受 PWA 限制，专注核心功能

在 HTTP 局域网环境下，PWA 的离线能力受限，建议：
1. 确保核心功能（浏览菜单、下单）不依赖离线
2. 提供「刷新」按钮，在网络恢复时手动刷新
3. 在页面上显示网络状态提示

### 4.3 如果必须启用 Service Worker

如果确实需要 PWA 离线能力，有以下选择：

1. **使用自签名 HTTPS**（见第五章）
2. **使用内网穿透**（如 cloudflared、frp）获取公网 HTTPS 地址（但违背「本地优先」原则）
3. **使用 localhost 访问**（仅适用于开发测试，不适用于生产环境）

## 五、自签名 HTTPS 方案评估

### 5.1 自签名证书在手机上的信任问题

**核心问题**：自签名证书不被手机操作系统信任，访问时会出现安全警告。

**iOS**：
- 访问自签名 HTTPS 网站时，Safari 会显示「此连接不是私密连接」
- 用户需要手动点击「显示详情」→「访问此网站」→「访问」
- **体验极差**，普通顾客无法完成此操作

**Android**：
- Chrome 会显示「您的连接不是私密连接」
- 用户需要点击「高级」→「继续前往」
- **体验较差**，但比 iOS 稍好

**微信内置浏览器**：
- 可能直接拦截自签名证书网站，无法访问（**未验证，建议实测**）

### 5.2 mkcert 生成局域网证书

**mkcert** 可以生成受信任的局域网证书，但需要将 CA 证书安装到每台设备上。

**步骤**：
```bash
# 安装 mkcert
brew install mkcert

# 安装本地 CA
mkcert -install

# 为局域网 IP 生成证书
mkcert 192.168.1.100 yuwen.local

# 生成文件：192.168.1.100+1.pem 和 192.168.1.100+1-key.pem
```

**问题**：
- 需要将 `rootCA.pem` 安装到每台顾客的手机上
- iOS 需要通过 AirDrop 或邮件发送证书，并在「设置」中手动安装
- **对于足浴店场景，让顾客安装证书不现实**

### 5.3 成本 vs 收益分析

| 方案 | 成本 | 收益 | 推荐度 |
|------|------|------|--------|
| **保持 HTTP** | 零 | 核心功能可用，PWA 离线受限 | ⭐⭐⭐⭐⭐ |
| **自签名 HTTPS** | 高（需配置证书） | 解锁 Service Worker 等 API | ⭐⭐ |
| **mkcert + 顾客装证书** | 极高（需顾客配合） | 同上 | ❌ |
| **内网穿透** | 中（需公网服务器） | 完整 HTTPS 支持 | ⭐（违背本地优先） |

**结论**：对于足浴店场景，**保持 HTTP 是最佳选择**。PWA 离线能力受限，但核心功能（浏览菜单、下单）不受影响。

### 5.4 内网穿透方案（备选）

如果未来确实需要 HTTPS，可考虑内网穿透：

- **cloudflared**：免费，无需公网 IP，但需要注册 Cloudflare 账号
- **frp**：需要公网服务器
- **bore**：轻量级，但稳定性一般

**注意**：这些方案都依赖外部服务，违背「本地优先」原则，且可能引入网络延迟。

## 六、扫码体验优化

### 6.1 二维码尺寸与张贴建议

**尺寸**：
- 最小尺寸：2cm × 2cm（约 80×80 像素 @ 300dpi）
- 推荐尺寸：5cm × 5cm（约 200×200 像素 @ 300dpi）
- 张贴高度：1.2m - 1.5m（顾客站立时手机相机容易对准）

**张贴位置**：
- 大堂入口显眼位置
- 收银台附近
- 等候区墙面

**二维码内容**：
- 使用高容错级别（H 级，30% 容错）
- 确保二维码颜色对比度高（黑底白码或白底黑码）
- 避免二维码被遮挡或反光

### 6.2 首屏加载速度优化

**局域网优势**：局域网内网速度快（通常 100Mbps+），延迟低（<1ms）。

**优化建议**：
1. **代码分割**：使用 Vite 的代码分割功能，按需加载
2. **资源压缩**：启用 Gzip/Brotli 压缩
3. **图片优化**：使用 WebP 格式，压缩图片体积
4. **预加载关键资源**：使用 `<link rel="preload">` 预加载首屏关键 JS/CSS
5. **减少首屏 JS 体积**：
   - 分析 bundle 体积：`vite build --report`
   - 移除未使用的依赖
   - 使用动态导入

**当前项目检查点**：
- 检查 `vite.config.ts` 是否启用了代码分割
- 检查 `index.html` 是否预加载了关键资源
- 检查是否有大型依赖（如 moment.js、lodash）可以替换

### 6.3 二维码承载更多信息

可以在 URL 中编码更多信息，区分不同场景：

| 场景 | URL 示例 | 用途 |
|------|----------|------|
| 大堂码 | `http://192.168.1.100:8080/guest/lobby` | 顾客进店扫码，选择房间/项目 |
| 房间码 | `http://192.168.1.100:8080/guest/room/101` | 顾客在房间内扫码，直接点单 |
| 桌号码 | `http://192.168.1.100:8080/guest/table/A12` | 餐厅场景，桌边扫码 |

**建议**：大堂码使用 `/guest/lobby` 路径，与房间码区分。

### 6.4 扫码后降级方案

**扫不出来怎么办**：
1. **提供短链**：在二维码旁边标注「如扫码失败，请手动输入 `http://192.168.1.100:8080`」
2. **提供文字说明**：在张贴位置添加文字说明，指导顾客手动输入
3. **提供备用二维码**：如果主二维码损坏，提供备用二维码

**网络异常处理**：
1. 在页面上显示网络状态提示
2. 提供「重试」按钮
3. 显示客服联系方式

## 八、总结

### 8.1 核心结论

1. **推荐使用局域网 IP 作为二维码 URL**，并通过路由器 DHCP 静态分配确保 IP 不变
2. **微信扫码可以打开 HTTP 局域网地址**，支持非标准端口
3. **HTTP 局域网环境下，Service Worker 无法注册**，PWA 离线功能受限
4. **语音识别功能可能不可用**，需提供手动输入降级方案
5. **自签名 HTTPS 方案成本高、体验差**，不推荐用于足浴店场景
6. **保持 HTTP 是最佳选择**，核心功能不受影响

### 8.2 风险与应对

| 风险 | 应对措施 |
|------|----------|
| IP 变化导致二维码失效 | 使用 DHCP 静态分配 + 定期测试 |
| 微信内置浏览器兼容性问题 | 提供系统相机扫码 + 手动输入降级 |
| 语音识别不可用 | 提供手动输入作为降级方案 |
| 顾客不会操作 | 在张贴位置添加文字说明 |

### 8.3 后续建议

1. **实测验证**：在真实环境中测试微信扫码、语音识别等功能
2. **用户培训**：培训店员指导顾客扫码
3. **监控告警**：设置监控，在服务不可用时及时告警
